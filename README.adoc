== M0TH3R@3

A set of retro terminal widgets, built with https://ratatui.rs/[Ratatui], and the displays made from them.
Everything looks best in `cool-retro-term`.

=== Workspace layout

`crates/widgets`::
  Shared library: terminal setup, the frame loop (`Program` trait, `run`), key-hold tracking, and generic widgets (menu with notification markers, notification queue, labeled gauge, fake diagnostics charts).
`crates/serve`::
  SSH server for any `widgets::Program`, built on https://github.com/warp-tech/russh[russh]. Each connected client gets its own session thread running the same frame loop as the local terminal. Modelled after https://github.com/ricott1/frittura-ssh[frittura-ssh] (which is GPL and therefore reimplemented rather than depended on).
`crates/mothership`::
  Ship management interface for players of the https://www.tuesdayknightgames.com/pages/mothership-rpg[Mothership TTRPG]: galaxy and star maps, crew, stock market, resources. Dutch in-game text. Runs in the local terminal or as an SSH server.
`crates/car`::
  In-car display skeleton: navigation, music and vehicle screens. Runs on demo data until a GPS receiver, a music player and vehicle telemetry are hooked up.

=== Running

[source,sh]
----
just run            # mothership, uses default.json / fallback.json
just run ship.json  # mothership with a specific save file
just car            # car display
just cool-run       # mothership in cool-retro-term
just serve          # mothership as an SSH server on 0.0.0.0:2222
----

=== Serving over SSH

[source,sh]
----
mothership --serve ship.json                      # listen on 0.0.0.0:2222
mothership --serve --listen 127.0.0.1:2299 ship.json
mothership --serve --host-key /var/lib/mothership/host_key ship.json
----

Players connect with `ssh -p 2222 <username>@<host>` and log in with the username and password from the save file (the login puzzle with `password_start` and attempt counts applies, exactly as on the login screen). Esc, Ctrl-C or Ctrl-D ends the session and writes the player's progress back to the save file.

The Ed25519 host key is generated on first start at `mothership_host_key` (ignored by git). Keep it: clients pin it in `known_hosts`.

=== Deploying on NixOS

The flake exports `packages.x86_64-linux.mothership` (and `car`) built with naersk, and a NixOS module `nixosModules.mothership` that runs the SSH server as a hardened systemd service under a dynamic user.

[source,nix]
----
{
  inputs.mothership.url = "github:wjehee/M0TH3RAT3";

  # in the host configuration:
  imports = [ inputs.mothership.nixosModules.mothership ];
  services.mothership = {
    enable = true;
    port = 2222;            # default
    openFirewall = true;
    initialStorage = ./ship.json;   # seeded into /var/lib/mothership on first start
  };
}
----

State lives in `/var/lib/mothership`: the save file `ship.json` and the host key. The seed file is only copied when no save exists, so redeploys keep the players' progress. The embedded SSH server is independent of the system `sshd`, so both can run on one machine on different ports.

`nix flake check` runs a NixOS VM test that boots the module, logs in over SSH with a password, explores a planet and checks that the save file was written and the host key survives a restart.
